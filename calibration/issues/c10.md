# calibration c10: unique() loses the order of the items

`unique([3, 1, 3, 2])` returns `[1, 2, 3]`; expected `[3, 1, 2]`.

`unique(xs)` in `calibration/c10.py` should give: xs without repeats, in the order of each item's first occurrence.

This is a calibration issue (calibration/README.md): a deliberate, small bug kept in this repository to qualify validators. A fix changes `calibration/c10.py` and sets its `FIXED` to `True`, so that the item's protected test (`tests/test_calibration.py`, class `C10`) runs.
