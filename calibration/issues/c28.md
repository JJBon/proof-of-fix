# calibration c28: normalize_spaces() leaves runs of three spaces

`normalize_spaces("a   b")` returns `'a  b'`; expected `"a b"`.

`normalize_spaces(s)` in `calibration/c28.py` should give: s with each run of whitespace collapsed to one space, and its ends stripped.

This is a calibration issue (calibration/README.md): a deliberate, small bug kept in this repository to qualify validators. A fix changes `calibration/c28.py` and sets its `FIXED` to `True`, so that the item's protected test (`tests/test_calibration.py`, class `C28`) runs.
